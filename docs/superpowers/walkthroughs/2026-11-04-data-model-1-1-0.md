# Walkthrough: Data Model 1.1.0 (positions, template links, one front field, edit times)

**Date:** 2026-11-04
**Status:** Completed & verified with scripted checks (no in-app run)

## Why
An audit found plays linked to formation templates by fuzzy name matching (so "Update" silently did nothing for some plays), roles guessed from labels (34 of 45 offensive formations counted an eligible player as a lineman), two fields for the defensive front, and no way to tell which of two differing copies was newer.

## What changed
1. **Schema + migrations** - `src/utils/playMigrations.ts` (new), `src/utils/playValidation.ts`, `src/types/playbook.ts`. `1.0.0` input is upgraded on every read path; upgrading twice changes nothing; explicit values are never overwritten.
2. **Positions** - inferred once from the label, falling back to alignment for ambiguous skill labels (X, Y, Z, H, F). `S` is left blank on defense because it means Sam in some schemes and Safety in others.
3. **Template links** - ids are resolved with the old matching rules once at migration, then only by id or exact name at runtime. Entry points that apply or save a template set the link.
4. **Front field** - `targetFront` removed from the type, presets, library, matrix and Inspector.
5. **Edit times** - every added or changed play is stamped in one place (`setPlaybook`); Firestore keeps it.
6. **Presets** - `INITIAL_PLAYBOOK` and `DEFAULT_FORMATIONS` are built through the same upgrade.

## Verification
- 27 migration/classifier checks and 10 storage/validation regression checks pass against the real presets: eligible players misclassified as linemen 34 -> 0, QB-alignment mismatches 1 -> 0, every preset play linked on both sides.
- `tsc -b` and `oxlint` clean.
- Contrast for the new Inspector text and Role select: 6.9 to 17.9 (text), 3.6 and 4.8 (borders).

## Not done (deliberately)
- Splitting `Player` into identity/alignment/assignment/style sub-objects: large, no behavior gain by itself, and it touches ~3,000 lines of preset data.
- Keeping a play's own assignment text when a formation template is applied (needs a decision for `#1/#2/#3` route mode).
- Tightening the `| string` unions.
